How our knee MRI models are built

From radiology reports and DICOM series to a leaderboard submission. Every component is our own code; only the ImageNet starting weights come from outside.

The pipeline

1 · Labels
Radiology reports4,407 training studies have text, not image labels
→
LLM reads each report12 findings × 5 states: positive, uncertain, mild, absent, not mentionedreport alone: gold 0.872
→
Soft labelsreport mixed with out-of-fold image predictions (self-training); weight per finding typegold 0.938
2 · Images
DICOM seriesseveral sequences per study, 10–60 slices each
→
Pick one series per viewsagittal, coronal, axial (fat-sat) + sagittal, coronal (non-fat-sat)
→
Fixed-mm crop around the kneev2: 4 views × 32 slices, 256 px
v5: 5 views, 96 slices, 384 px
v6: 448 px (testing)
3 · Models
2.5D model (B0, ConvNeXt)all 32 slices of a view → CNN per slice → attention over slices → transformer across views → 12 outputsB0 alone: LB 0.935
Window model ★every 3-slice window (previous, slice, next) → CNN → add view and position → one attention per finding over all windows → 12 outputs. Trained on 32 random windows per step, 20 epochs, average of the last 3 epochs.ConvNeXt v2 alone: LB 0.948
4 · Checks
Gold-5858 studies with radiologist image labels, never trained on
→
5-fold CVfolds grouped by hospital
→
Final modelsretrained on all data, several random seeds
5 · Submission
Hidden test DICOMsoffline Kaggle GPU notebook
→
Same preprocessing, every modelplus the mirror image (left ↔ right knee), averaged
→
Average per family, equal vote→ submission.csv → leaderboard
